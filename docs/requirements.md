# AIOps Copilot 需求说明

## 1. 项目背景

在日常运维过程中，系统告警通常分散在监控平台、日志平台、部署记录和历史故障文档中。

开发人员收到告警后，需要人工查询多个系统，并结合经验判断故障原因，存在以下问题：

- 告警信息分散，定位耗时较长
- 需要人工查询指标、日志和发布记录
- 新人缺少故障排查经验
- 历史故障知识难以复用
- 告警通常只能反映现象，不能直接给出根因

因此，希望构建一个基于大模型 Agent 的智能故障分析助手，
帮助开发和运维人员快速完成告警分析、证据收集和排查建议生成。

---

## 2. 项目目标

构建一个可以在本地运行的 AIOps Copilot，实现：

1. 用户提交一条或一组系统告警
2. Agent 自动理解告警内容
3. Agent 根据需要调用监控指标、日志、部署记录等工具
4. Agent 检索本地故障知识库
5. Agent 综合多个证据分析可能根因
6. 输出结构化 RCA 分析报告
7. 展示 Agent 的工具调用过程和排查 Checklist

项目重点体现：

- LLM 调用
- Agent 自主决策
- Tool Calling
- RAG 知识库
- 结构化输出
- 可解释的证据链
- AI 辅助研发过程

---

## 3. 目标用户

### 3.1 后端开发人员

希望快速了解线上异常可能原因，辅助定位问题。

### 3.2 运维人员

希望根据告警快速获得初步故障分析和排查路径。

### 3.3 初级开发人员

缺少线上故障处理经验，需要系统化的排查建议。

---

## 4. 核心使用场景

### 场景一：订单服务接口大量超时

用户提交告警：

- 服务：order-service
- 环境：production
- 告警：接口 P99 延迟超过 2 秒
- 错误率超过 5%

Agent 自动执行：

1. 查询 order-service 监控指标
2. 查询最近错误日志
3. 查询最近部署记录
4. 检索数据库连接池耗尽相关知识
5. 综合分析故障原因
6. 输出 RCA 报告

预期分析结果：

- 数据库连接池使用率达到 95%
- 日志出现获取数据库连接超时
- 最近发布增加了复杂查询逻辑
- 初步判断可能是慢 SQL 或数据库连接池耗尽
- 建议检查慢 SQL、数据库连接数和发布前后指标

## 5. 功能范围

## 5.1 告警管理

### 功能描述

用户可以创建、查看和管理告警记录。

### 功能要求

- 创建告警
- 查看告警列表
- 查看告警详情
- 告警状态展示
- 支持填写服务名、环境、告警标题、告警内容

### 告警字段

- 告警 ID
- 服务名称
- 环境
- 告警标题
- 告警原始内容
- 创建时间
- 分析状态

---

## 5.2 AI 告警分析

### 功能描述

用户可以对指定告警发起 AI 分析。

### 功能要求

- 启动分析任务
- 调用 Agent 进行故障分析
- 自动选择合适的工具
- 获取指标、日志和部署信息
- 结合知识库进行分析
- 输出结构化分析报告
- 保存分析结果

---

## 5.3 监控指标查询工具

Agent 可以查询指定服务的模拟监控指标。

支持指标：

- CPU 使用率
- 内存使用率
- P99 延迟
- 错误率
- 数据库连接池活跃连接数
- 数据库连接池最大连接数
- Redis 延迟
- JVM GC 等指标

第一期使用 Mock 数据，不接入真实 Prometheus。

---

## 5.4 日志查询工具

Agent 可以查询指定服务最近的错误日志。

支持：

- 根据服务名查询
- 根据关键词过滤
- 返回错误日志时间、级别、内容
- 模拟日志查询耗时和异常情况

第一期使用本地 JSON 或数据库中的模拟日志。

---

## 5.5 部署记录查询工具

Agent 可以查询服务最近的部署记录。

支持：

- 查询最近发布版本
- 查询发布时间
- 查询发布内容
- 辅助判断故障是否与最近发布有关

---

## 5.6 RAG 知识库

### 功能描述

通过向量检索获取与当前故障相关的运维知识。

### 知识库内容

- 数据库连接池耗尽
- 慢 SQL
- Redis 延迟升高
- JVM 高 GC
- JVM OOM
- 线程池耗尽
- CPU 使用率过高
- 内存泄漏
- 服务接口超时
- 发布回归问题

### 功能要求

- 支持加载 Markdown 知识文档
- 文档切分和向量化
- 向量检索相关知识
- 将召回内容提供给 Agent
- 在 RCA 报告中展示相关知识

---

## 5.7 RCA 报告

AI 分析完成后，输出结构化报告。

报告至少包含：

- 故障摘要
- 故障严重等级
- 可能根因列表
- 每个根因的置信度
- 根因分析依据
- 证据链
- 建议排查步骤
- 相关知识文档
- 当前结论是否确定

### 报告示例

```json
{
  "incidentSummary": "订单服务接口延迟升高，错误率同步上升",
  "severity": "HIGH",
  "possibleRootCauses": [
    {
      "cause": "数据库连接池耗尽",
      "confidence": 90,
      "reasoning": "连接池使用率达到95%，同时日志出现获取数据库连接超时"
    }
  ],
  "investigationSteps": [
    {
      "order": 1,
      "action": "检查慢SQL和数据库连接池状态",
      "purpose": "确认数据库连接长期占用的原因"
    }
  ]
}
